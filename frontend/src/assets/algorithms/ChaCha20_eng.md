ChaCha20 is a stream cipher designed by Daniel J. Bernstein in 2008 as an improved version of Salsa20. As a **cryptographically secure pseudorandom generator (CSPRNG)**, ChaCha20 has found wide application in network protocols (TLS 1.3, WireGuard, SSH) and is currently one of the most popular stream ciphers in the world. The keystream generated by ChaCha20 can serve as a source of high-quality pseudorandom bits with cryptographic guarantees.

### Mathematical Explanation

ChaCha20 is a stream cipher based on the **ARX** (Add-Rotate-XOR) construction – it uses only addition modulo $2^{32}$, bitwise rotations, and XOR.

#### Internal State

The ChaCha20 state is a $4 \times 4$ matrix of 32-bit words (512 bits total):

$$
\begin{bmatrix}
c_0 & c_1 & c_2 & c_3 \\
k_0 & k_1 & k_2 & k_3 \\
k_4 & k_5 & k_6 & k_7 \\
b & n_0 & n_1 & n_2
\end{bmatrix}
$$

where:

- $c_0, c_1, c_2, c_3$ – **ChaCha constants** ("expand 32-byte k" in ASCII): `0x61707865, 0x3320646e, 0x79622d32, 0x6b206574`
- $k_0 \ldots k_7$ – **256-bit key** (8 × 32-bit)
- $b$ – **32-bit block counter**
- $n_0, n_1, n_2$ – **96-bit nonce** (3 × 32-bit)

#### Quarter-round Operation

The basic ChaCha20 operation is the **quarter-round** – a mixing function operating on 4 32-bit words:

```
QUARTERROUND(a, b, c, d):
    a += b; d ^= a; d <<<= 16
    c += d; b ^= c; b <<<= 12
    a += b; d ^= a; d <<<= 8
    c += d; b ^= c; b <<<= 7
```

where:

- += denotes addition modulo $2^{32}$
- ^= denotes XOR
- <<<= denotes left bitwise rotation

**Why these specific rotations (16, 12, 8, 7)?**

- Chosen empirically for maximum diffusion
- Each rotation mixes bits differently
- 4 rounds give full avalanche effect (1 input bit change → changes 16 output bits on average)

#### Mixing Rounds

One **double-round** of ChaCha20 consists of:

1. **Column rounds** – quarter-round on columns:

   ```
   QUARTERROUND(0, 4,  8, 12)
   QUARTERROUND(1, 5,  9, 13)
   QUARTERROUND(2, 6, 10, 14)
   QUARTERROUND(3, 7, 11, 15)
   ```

2. **Diagonal rounds** – quarter-round on diagonals:
   ```
   QUARTERROUND(0, 5, 10, 15)
   QUARTERROUND(1, 6, 11, 12)
   QUARTERROUND(2, 7,  8, 13)
   QUARTERROUND(3, 4,  9, 14)
   ```

**ChaCha20 performs 10 double-rounds (20 quarter-rounds)** – hence the name "ChaCha20".

#### Block Generation

The process of generating a 512-bit keystream block:

1. **Initialize**: Load initial state (constants, key, counter, nonce)
2. **Copy state**: $\text{working} \leftarrow \text{state}$
3. **20 mixing rounds**: Execute 10 double-rounds on $\text{working}$
4. **Add initial state**: $\text{output} \leftarrow \text{working} + \text{state}$ (modulo $2^{32}$ per word)
5. **Increment counter**: $b \leftarrow b + 1$
6. **Result**: 512 bits of keystream

**Why add the initial state?**

- Prevents "backward tracing" attacks
- Each block is a function of both the state before and after mixing
- Increases cryptographic security

#### As CSPRNG

When ChaCha20 is used as a CSPRNG:

- **Key**: 256 bits of entropy (e.g., from /dev/urandom)
- **Nonce**: 96 bits of entropy or deterministic value
- **Counter**: Starts at 0, incremented for each block
- **Output**: Keystream treated as pseudorandom bits

One seed (key + nonce) can generate $2^{32} \times 512 = 2{,}199{,}023{,}255{,}552$ bits (~2 terabytes) before exhausting the counter.

### ChaCha Variants

#### ChaCha20 (standard)

- 20 rounds (10 double-rounds)
- Full cryptographic security
- Standard variant used in TLS, WireGuard

#### ChaCha12

- 12 rounds (6 double-rounds)
- Faster while maintaining high security
- Used in some mobile applications

#### ChaCha8

- 8 rounds (4 double-rounds)
- Fastest variant
- Still very secure for most applications

#### XChaCha20

- Extended nonce to 192 bits (instead of 96)
- Enables random nonce selection without collisions
- Used in libsodium

### Key Code Fragment

```rust
use chacha20::ChaCha20;
use chacha20::cipher::{KeyIvInit, StreamCipher};

fn chacha20_bit_stream(seed: &[u8; 32], nonce: &[u8; 12],
                        n_bits: usize) -> Vec<u8> {
    // Initialize ChaCha20
    let mut cipher = ChaCha20::new(seed.into(), nonce.into());

    // Calculate required number of bytes
    let n_bytes = (n_bits + 7) / 8;
    let mut buffer = vec![0u8; n_bytes];

    // Generate keystream
    cipher.apply_keystream(&mut buffer);

    // Convert to bits (if needed)
    buffer
}
```

The Rust implementation uses the dedicated `chacha20` library ensuring constant-time operations (protection against timing attacks).

### Applications

**Cryptographic applications:**

- **TLS 1.3** – ChaCha20-Poly1305 as preferred cipher on devices without AES-NI
- **WireGuard VPN** – uses ChaCha20 for tunnel encryption
- **SSH** – chacha20-poly1305@openssh.com cipher
- **Signal Protocol** – message encryption in messengers (Signal, WhatsApp)
- **Tor** – circuit encryption in the anonymizing network

**As CSPRNG:**

- **Cryptographic key generation** – AES, RSA, ECDSA keys
- **Initialization vectors (IV)** – for block ciphers
- **Nonce generation** – one-time values for protocols
- **Salts** – for password hashing (bcrypt, Argon2)
- **Token generation** – session tokens, CSRF tokens

**Advantages over AES-CTR:**

- **Faster on CPUs without AES-NI** – mobile devices, embedded systems
- **Constant-time** – resistant to timing attacks without special hardware
- **Simpler** – easier to implement without errors
- **No weak keys** – every 256-bit key is equally good

**Limitations:**

- **Slower than AES-NI** – on processors with hardware AES acceleration
- **Larger code** – implementation takes more space than AES
- **Nonce reuse catastrophic** – using the same (key, nonce) twice breaks encryption

### Cryptographic Quality

#### Security analysis:

**Theoretical security:**

- **No known practical attacks** on ChaCha20 (20 rounds)
- **7.5 rounds of ChaCha** broken in theoretical attacks (margin: 12.5 rounds)
- **ChaCha8** still considered secure (margin: 0.5 rounds)

**Cryptanalytic tests:**

- **Differential cryptanalysis**: No practical attacks
- **Linear cryptanalysis**: Resistant
- **Algebraic attacks**: No progress
- **Related-key attacks**: Not applicable (no related keys in practice)

**Cryptographic advantages:**

1. **256-bit key**: Resistant to brute-force (even for quantum computers)
2. **ARX construction**: Simple, well-studied construction
3. **No lookup tables**: No cache-timing vulnerabilities
4. **Parallelizable**: Each block independent (SIMD, GPU)

### Historical Context and Trivia

**History:**

- **2005**: Daniel J. Bernstein designs **Salsa20**
- **2008**: **ChaCha** as improved version of Salsa20
- **2014**: Google adopts ChaCha20-Poly1305 in Chrome/Android (lack of AES-NI on ARM)
- **2018**: **RFC 8439** standardizes ChaCha20-Poly1305
- **2020**: TLS 1.3 prefers ChaCha20 on mobile devices

**Motivation for creation:**

- Need for fast stream cipher for devices without AES acceleration
- Salsa20 was good, but ChaCha improved diffusion (diagonal rounds)
- Alternative to AES avoiding patents and specialized hardware

**Daniel J. Bernstein:**

- Professor of mathematics and computer science (University of Illinois Chicago)
- Creator of: Curve25519, Ed25519, NaCl/libsodium
- Known for designing algorithms resistant to timing attacks

**Trivia:**

- Name "ChaCha" comes from the Latin American dance (similar to "Salsa")
- **ChaCha20-Poly1305** combines encryption (ChaCha20) with authentication (Poly1305) in AEAD
- Google implemented ChaCha20 in BoringSSL (OpenSSL fork) and contributed to standardization
- WireGuard (Linus Torvalds: "work of art") uses exclusively ChaCha20 for encryption
- ChaCha20 is used in **>80% of mobile TLS connections** (Chrome, Android)
- ChaCha20 implementation in 100 lines of C is secure and fast

### Computational Complexity

- **Generation step** (512-bit block): $O(1)$ – 80 quarter-rounds × 4 operations = 320 operations
- **Memory**: $O(1)$ – 64 bytes state (16 × 32-bit)
- **Initialization**: $O(1)$ – setting initial state

**Detailed analysis:**

- Each quarter-round: 4 additions + 4 XOR + 4 rotations = 12 operations
- 80 quarter-rounds: 960 operations for 512 bits = ~1.9 operations/bit
- Very efficient for cryptographic construction

**Practical performance:**

- Python (pure): ~10-20 MB/s
- Python (C library): ~100-200 MB/s
- C (optimized): ~500-800 MB/s
- Rust: ~400-700 MB/s
- Assembly (SIMD): ~2-4 GB/s

**Comparison with AES:**

- On CPU without AES-NI: **ChaCha20 2-3× faster**
- On CPU with AES-NI: **AES 3-4× faster**
- On ARM/mobile: **ChaCha20 dominates**

### Computational Examples

#### Example 1: Quarter-round

For input $(a, b, c, d) = (0x11111111, 0x01020304, 0x9b8d6f43, 0x01234567)$:

```
Step 1: a += b; d ^= a; d <<<= 16
    a = 0x11111111 + 0x01020304 = 0x12131415
    d = 0x01234567 ^ 0x12131415 = 0x13305172
    d = rotl(0x13305172, 16) = 0x51721330

Step 2: c += d; b ^= c; b <<<= 12
    c = 0x9b8d6f43 + 0x51721330 = 0xecff8273
    b = 0x01020304 ^ 0xecff8273 = 0xedfd8177
    b = rotl(0xedfd8177, 12) = 0xd8177edf

... (2 more steps)
```

Result: Completely changed values of all 4 words.

#### Example 2: State initialization

For key `key = [0x03020100, ..., 0x1f1e1d1c]` and nonce `[0, 0, 0]`:

```
Initial state:
[0x61707865, 0x3320646e, 0x79622d32, 0x6b206574]  // Constants
[0x03020100, 0x07060504, 0x0b0a0908, 0x0f0e0d0c]  // Key (part 1)
[0x13121110, 0x17161514, 0x1b1a1918, 0x1f1e1d1c]  // Key (part 2)
[0x00000000, 0x00000000, 0x00000000, 0x00000000]  // Counter + Nonce
```

#### Example 3: PRNG stream generation

```rust
// Seed (256-bit key)
let key = [0u8; 32];  // All zeros (for example only!)

// Nonce (96-bit)
let nonce = [0u8; 12];

// Generate 1000 bits
let stream = chacha20_rng(&key, &nonce, 1000);

// stream[0..125] contains 1000 pseudorandom bits
```

**Security**: For real CSPRNG, key must be 256 bits of entropy from /dev/urandom or similar source.

#### Example 4: State space

- **Key**: $2^{256}$ possible values
- **Nonce**: $2^{96}$ possible values
- **Counter**: $2^{32}$ blocks per (key, nonce)
- **Total space**: $2^{256} \times 2^{96} \times 2^{32} = 2^{384}$ blocks

This gives $2^{393}$ bits of possible stream.

ChaCha20 represents a modern approach to stream cipher design: construction simplicity, high performance, proven security, and resistance to side-channel attacks. It is currently the gold standard for encryption on mobile devices and an ideal choice for CSPRNG in applications requiring cryptographic guarantees.
