The xorshift/xoshiro family represents a modern approach to pseudorandom generator design, combining extreme speed with excellent statistical quality. **Xoshiro256\*\*** (xor-shift-rotate) is the latest evolution of this family, designed by David Blackman and Sebastiano Vigna, offering practically the best quality-to-performance ratio among all non-cryptographic generators.

### History and Evolution

#### Xorshift (Marsaglia, 2003)

Original **xorshift** proposed by George Marsaglia used only XOR and shift operations:

$$x_{n+1} = x_n \oplus (x_n << a) \oplus (x_n >> b) \oplus (x_n << c)$$

**Advantages**: Extremely simple and fast\
**Disadvantages**: Failures in some statistical tests, especially for small states

#### Xorshift+ / Xorshift\* (2014-2015)

Vigna and Blackman introduced a **scrambler** – additional output permutation function:

- **Xorshift+**: Adding two states
- **Xorshift\***: Multiplication by constant

This significantly improved statistical quality.

#### Xoshiro/Xoroshiro (2016-2018)

Latest family uses **rotation** instead of shifts + improved state update schemes:

- **xoroshiro128+**: 128-bit state, + scrambler
- **xoshiro256\*\***: 256-bit state, \*\* scrambler (best)
- **xoshiro512\*\***: 512-bit state (for longest simulations)

### Mathematical Explanation of xoshiro256\*\*

The xoshiro256\*\* generator uses a state composed of four 64-bit words and an advanced scrambler.

#### Generator State

State is four 64-bit integers:

$$\text{state} = (s_0, s_1, s_2, s_3)$$

Total state size: $4 \times 64 = 256$ bits.

#### Output Function (scrambler "\*\*")

64-bit output is generated by double multiplication and rotation operations on $s_1$:

$$\text{output} = \text{rotl}(s_1 \times 5, 7) \times 9$$

where $\text{rotl}(x, k)$ denotes left bitwise rotation by $k$ positions.

**Why this scrambler?**

- **Multiplication × 5**: Propagates changes through entire word
- **Rotation by 7**: Mixes bit positions
- **Multiplication × 9**: Second diffusion layer
- Constants (5, 7, 9) chosen empirically for maximum avalanche

#### State Update

State is updated through a series of XOR and rotation operations:

```
t ← s_1 << 17          // Helper shift
s_2 ← s_2 ⊕ s_0        // State mixing
s_3 ← s_3 ⊕ s_1
s_1 ← s_1 ⊕ s_2
s_0 ← s_0 ⊕ s_3
s_2 ← s_2 ⊕ t          // Add shift
s_3 ← rotl(s_3, 45)    // Final rotation
```

**Update analysis:**

- Each state word is a function of at least two previous words
- XOR ensures reversibility (full period)
- Rotation adds nonlinearity
- Numbers (17, 45) chosen for maximum diffusion

#### Mathematical Properties

**Period**: $2^{256} - 1$ – practically inexhaustible

- All $2^{256}$ states except zero state (0,0,0,0)
- For comparison: number of atoms in universe $\approx 2^{265}$

**Linear complexity**: 256 bits (full)

**Reversible**: Can compute previous state from known state (but non-trivially)

### Key Code Fragment

```csharp
public class Xoshiro256StarStar
{
    private ulong s0, s1, s2, s3;

    // Helper function: left rotation
    private static ulong RotateLeft(ulong x, int k)
    {
        return (x << k) | (x >> (64 - k));
    }

    public ulong Next()
    {
        // Output function (scrambler **)
        ulong result = RotateLeft(s1 * 5, 7) * 9;

        // State update
        ulong t = s1 << 17;

        s2 ^= s0;
        s3 ^= s1;
        s1 ^= s2;
        s0 ^= s3;

        s2 ^= t;
        s3 = RotateLeft(s3, 45);

        return result;
    }

    // Initialization (often with SplitMix64)
    public void Seed(ulong seed)
    {
        var sm = new SplitMix64(seed);
        s0 = sm.Next();
        s1 = sm.Next();
        s2 = sm.Next();
        s3 = sm.Next();
    }
}
```

C# implementation uses native `ulong` types and efficient processor bit operations.

### xoshiro Family Variants

#### xoshiro256\*\* (implemented)

- State: 256 bits (4 × 64-bit)
- Scrambler: \*\* (double multiplication)
- **Best general choice**

#### xoshiro256+

- Scrambler: + (addition s0 + s3)
- Faster, but slightly weaker statistically
- Good for floating-point applications

#### xoroshiro128\*\*

- State: 128 bits (2 × 64-bit)
- Smaller memory footprint
- Sufficient for most applications

#### xoshiro512\*\*

- State: 512 bits (8 × 64-bit)
- Even longer period ($2^{512}-1$)
- For extremely long simulations

### Applications

**Practical applications:**

- **Scientific simulations** – particle physics, computational biology, Monte Carlo
- **Computer games** – procedural generation, AI, particle systems
- **Standard libraries** – Rust `rand` crate uses xoshiro by default
- **Performance benchmarks** – testing algorithms on large datasets
- **Machine learning** – weight initialization, dropout, data augmentation

**Advantages over Mersenne Twister:**

- **256 times smaller memory usage**: 32 bytes vs 2.5 KB
- **Faster initialization**: Instant vs hundreds of cycles
- **Better quality**: Passes all tests (MT has BigCrush problems)
- **Jump functions**: Easy creation of independent streams

**Limitations:**

- **Not for cryptography**: State can be reconstructed from ~4 64-bit outputs
- **Requires good initialization**: Zero state (0,0,0,0) is invalid

### Computational Complexity

- **Generation step**: $O(1)$ – constant number of bit operations
- **Memory**: $O(1)$ – 32 bytes (4 × 64-bit)
- **Initialization**: $O(1)$ – 4 SplitMix64 calls

**Detailed operation analysis per step:**

- 2× 64-bit multiplication (scrambler)
- 7× 64-bit XOR
- 2× bitwise rotation
- 1× bit shift

**Total**: ~8-12 CPU cycles per 64 output bits (0.125-0.19 cycles/bit)

### Computational Examples

#### Example 1: Basic iteration

Initial state: $s_0=1$, $s_1=2$, $s_2=3$, $s_3=4$

**Output:**

```
result = rotl(2 * 5, 7) * 9
       = rotl(10, 7) * 9
       = 1280 * 9
       = 11520
```

**State update:**

```
t = 2 << 17 = 262144

s_2 = 3 ⊕ 1 = 2
s_3 = 4 ⊕ 2 = 6
s_1 = 2 ⊕ 2 = 0
s_0 = 1 ⊕ 6 = 7

s_2 = 2 ⊕ 262144 = 262146
s_3 = rotl(6, 45) = 12884901888

New state: (7, 0, 262146, 12884901888)
```

#### Example 3: Scrambler comparison

For same state (before scrambler) $s_1 = 12345$:

**Xoshiro256+**:

```
output = s0 + s3 = 1 + 4 = 5
```

**Xoshiro256\*\***:

```
output = rotl(12345 * 5, 7) * 9 = ... (much more "random" value)
```

Double multiplication gives better avalanche.

#### Example 4: SplitMix64 initialization

```python
seed = 42
sm = SplitMix64(seed)

s0 = sm.next()  # e.g., 0x5B2A3D847F6E91C2
s1 = sm.next()  # e.g., 0xA7C4E9F1D3B82056
s2 = sm.next()  # e.g., 0x3F8D6C2B91E54A73
s3 = sm.next()  # e.g., 0xE1A9C5D7F4B38062

xoshiro = Xoshiro256StarStar(s0, s1, s2, s3)
```

SplitMix64 ensures state is "good" (no bad correlations).

Xoshiro256\*\* represents the pinnacle of modern non-cryptographic generator design – perfect balance between simplicity, speed, and statistical quality. It is probably the best choice for most applications not requiring cryptographic guarantees.
