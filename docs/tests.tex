\section{Wprowadzenie}

\subsection{Cel dokumentu}

Niniejszy dokument stanowi raport z przeprowadzonych testów systemu IO\_RNG, obejmujący testowanie funkcjonalne, integracyjne oraz testy akceptacyjne aplikacji. Raport zawiera szczegółową dokumentację znalezionych błędów, przeprowadzonych napraw oraz statystyki wykrytych problemów podczas procesu testowania.

\subsection{Zakres testów}

Proces testowania obejmował następujące obszary:

\begin{itemize}
    \item \textbf{Testy funkcjonalne} - weryfikacja poprawności działania poszczególnych modułów systemu (generatory, testy algorytmów, historia wyników)
    \item \textbf{Testy integracyjne} - sprawdzenie współpracy komponentów frontend-backend, komunikacji z bazą danych oraz integracji z algorytmami w różnych językach
    \item \textbf{Testy użyteczności} - ocena interfejsu użytkownika, przepływu pracy, intuicyjności funkcji
    \item \textbf{Testy wydajnościowe} - pomiar czasów wykonania testów algorytmów, generowania raportów PDF, obsługi dużych zbiorów danych
    \item \textbf{Testy walidacji danych} - weryfikacja poprawności walidacji parametrów wejściowych, obsługi błędnych danych
    \item \textbf{Testy jednostkowe backendu} - szczegółowe testy komponentów serwerowych
    \item \textbf{Testy API} - weryfikacja endpointów REST API
\end{itemize}

\subsection{Metodologia testowania}

Testy przeprowadzono w następujący sposób:

\begin{enumerate}
    \item Testowanie manualne funkcjonalności przez zespół
    \item Testowanie automatyczne z wykorzystaniem narzędzi (tam gdzie to możliwe)
    \item Analiza logów błędów i zachowań systemu
    \item Dokumentacja przypadków testowych i scenariuszy użycia
    \item Raportowanie błędów i śledzenie procesu naprawy
\end{enumerate}

\subsection{Struktura testów jednostkowych}

Testy jednostkowe realizują zasadę \textbf{F.I.R.S.T.}:
\begin{itemize}
    \item \textbf{Fast} - szybkie wykonanie ($<$ 100ms każdy)

\section{Szczegółowa dokumentacja znalezionych problemów}

\subsection{Problem \#1: Brak funkcji usuwania całej historii testów}

\begin{tcolorbox}[colback=red!5!white,colframe=red!75!black,title=Błąd UI - Priorytet: WYSOKI]
\textbf{Opis problemu:}

Podczas testów manualnych zaobserwowano, że użytkownik musi usuwać wyniki testów pojedynczo, co jest bardzo czasochłonne przy dużej liczbie wykonanych testów (100+ wyników). Brak globalnej funkcji czyszczenia historii.

\textbf{Scenariusz testowy:}
\begin{enumerate}
    \item Wykonano 150 testów algorytmów
    \item Próba wyczyszczenia historii przed rozpoczęciem nowej sesji testowej
    \item Konieczność ręcznego usuwania każdego wyniku z osobna
\end{enumerate}

\textbf{Oczekiwane zachowanie:}

System powinien oferować przycisk "Usuń całą historię" z potwierdzeniem akcji, umożliwiający jednorazowe wyczyszczenie wszystkich wyników testów.

\textbf{Status:} \textcolor{green}{NAPRAWIONE}

\textbf{Implementowane rozwiązanie:}

Dodano przycisk "Clear All History" w komponencie historii testów z modalem potwierdzenia. Backend endpoint: \texttt{DELETE /api/test-results/clear-all/}
\end{tcolorbox}

\subsection{Problem \#2: Brak możliwości zaznaczania wszystkich testów jednym przyciskiem}

\subsection{Problem \#7: Nieoptymalna implementacja Blum-Blum-Shub}

Weryfikacja techniczna wykazała jednak obecność krytycznych błędów w kodzie źródłowym biblioteki, które uniemożliwiały poprawne przeprowadzenie procedur testowych. Autorskie implementacje, choć poprawne funkcjonalnie, mogą ustępować rozwiązaniu bibliotecznemu pod względem efektywności obliczeniowej oraz stopnia formalnej weryfikacji (pewności) wyników.

\subsection{Problem \#9: Problemy ze ścieżkami do plików (Kompatybilność OS)}

\begin{tcolorbox}[colback=magenta!5!white,colframe=magenta!75!black,title=Problem Projektowy - Priorytet: WYSOKI]
\textbf{Opis problemu:}

Ze względu na pracę zespołu w środowisku heterogenicznym (systemy Windows oraz Linux), występowały błędy związane z różnym formatowaniem ścieżek do plików wykonywalnych w bazie danych. W celu rozwiązania problemu opracowano i uruchomiono skrypt migracyjny \texttt{update\_paths.py}, który ujednolicił wpisy w bazie.

\textbf{Status:} \textcolor{green}{NAPRAWIONE}

\textbf{Uzasadnienie:}

Różne systemy operacyjne stosują odmienne konwencje zapisu ścieżek (np. różnica w separatorach katalogów: \texttt{\textbackslash} w Windows vs \texttt{/} w Linux) oraz inną strukturę katalogów głównych. Przechowywanie ścieżek bezwzględnych uniemożliwiało uruchomienie testów na innej maszynie niż ta, na której dodano generator. Konwersja na ścieżki relatywne oraz implementacja dynamicznego ich rozwiązywania w backendzie (z użyciem biblioteki \texttt{pathlib}) była konieczna dla zapewnienia przenośności projektu i spójności środowiska deweloperskiego.
\end{tcolorbox}


\subsection{Problem \#10: Błędy matematyczne i algorytmiczne w testach Diehard}
\begin{tcolorbox}[colback=violet!5!white,colframe=violet!75!black,title=Problem Implementacyjny - Priorytet: KRYTYCZNY]
\textbf{Opis problemu:}
Wszystkie 15 testów statystycznych Diehard zawierały błędy matematyczne i algorytmiczne powodujące nieprawidłowe wyniki. Dobre generatory (NumPy, Python random) były błędnie odrzucane, podczas gdy słabe generatory (LCG) mogły być akceptowane. Zidentyfikowano i naprawiono 22 krytyczne błędy.
\textbf{Status:} \textcolor{green}{NAPRAWIONE}
\textbf{Najważniejsze poprawki:}
\begin{itemize}
    \item \textbf{Birthday Spacings Test}: Fundamentalny błąd -- liczył kolizje urodzin zamiast duplikaty odstępów między datami.
    
    \item \textbf{Squeeze Test}: Błędny punkt startowy ($0.0$ zamiast $2^{31}$), nieprawidłowa wartość oczekiwana (47 zamiast 21.5).
    
    \item \textbf{OPSO Test}: $\lambda > 2000$ (niestabilny Poisson) -- zaimplementowano strategię bloków z testem Fishera.
    
    \item \textbf{Parking Lot Test}: Dodano model saturacji (jamming limit przy ~1440 dyskach).
    
    \item \textbf{Overlapping Sums Test}: Ignorowano korelację $\rho \approx 0.9$ -- zastosowano korekcję Bartletta.
    
    \item \textbf{Runs Test}: Błędne $P(\text{run} \geq 7) = (1/2)^7$ zamiast $(1/2)^6$.
\end{itemize}
\textbf{Uzasadnienie:}
Błędy w testach Diehard uniemożliwiały rzetelną ocenę jakości generatorów -- system odrzucał dobre generatory lub akceptował słabe. Po poprawkach wszystkie testy osiągają 100\% skuteczności dla dobrych generatorów oraz prawidłowo wykrywają słabe (LCG: 0\% pass rate). Naprawiono 908 linii w pliku \texttt{run\_rng\_test.py}.
\end{tcolorbox}
